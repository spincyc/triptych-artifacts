# Triptych artifacts

Exact archival assets, browser-print render products and font software, and
disposable browser-cache candidates for
[Triptych](https://github.com/spincyc/triptych). The Git tree contains delivery
manifests, cache-candidate records and preservation tools; payloads are attached
to immutable releases.

Each delivery manifest records the original logical path, SHA-256, size, media
type and archive membership. The source repository retains the controlling
source identity, edition, rights record and page or line mapping. Downloading an
asset does not extend the distribution rights recorded for it.

The evidence release preserves exact source and historical publication bytes
from Triptych commit `2f23107c105e1f91f3cfebb64027ace149142416`. The print
release preserves the 278 PDFs served by the public site when the migration
was prepared, each checked against its published manifest digest. These are
archived print snapshots; current editions can be generated from their canonical
plaintext sources with Triptych's `print-document` tool. The review-handoff
release preserves the original five split ZIP chunks, including their embedded
PDFs, with exact chunk hashes and a reconstruction manifest.

Project-created metadata and software retain the source project's licenses.
Third-party source works and acquired facsimiles retain their individual rights;
see the original artifact records and `THIRD_PARTY.md` at the source commit.

The `papal-inputs-84c2f7e-v1` release preserves all 372 original frozen papal
release-input JSON and JSONL snapshots (685,669,809 exact bytes).
`papal-input-delivery.json` retains their original paths, hashes, sizes and
archive membership. Compact checked metadata in Triptych supports ordinary
reader validation; this archive retains the full original evidence for explicit
audit and offline replay. Storage relocation grants no new review or approval.

Browser-cache downloads are listed separately in
[`browser-product-candidates.json`](browser-product-candidates.json).
The `browser-products-e1ca91b-v1` candidate contains 12 generated families:
27,408 files and 200,635,886 uncompressed bytes. Its archive contains only the
cache marker, strict candidate index and family `key/data/` trees; the current
checkout builds its own aggregate.

These bytes are untrusted, disposable cache candidates. Only the current
Triptych checkout's committed `release/browser-products.json`, current canonical
inputs and complete path/hash/size checks can admit them for use. The archive
and its checksums establish transport identity, not source authority, editorial
approval or publication permission. The release README explains how to verify
the download and import it with a current checkout containing the strict
bootstrap helper and candidate-aware cache support. The origin commit records
the generated bytes; it predates that bootstrap helper.

The `browser-products-e300fe6332cb-v1` candidate matches the current descriptor
from Triptych `7b9daae87c`: 12 families, 27,414 files and 200,711,303
uncompressed data bytes. It follows the same untrusted-candidate acceptance
contract; prior immutable candidates remain available.

Browser-print asset delivery is indexed separately in
[`browser-print-projections.json`](browser-print-projections.json) and
[`browser-print-fonts.json`](browser-print-fonts.json). The
`web-print-projections-7b9daae-v1` release carries 39 server-guide SVGs and 21
selected generic TikZ SVGs: 60 render products and 56,060,198 payload bytes.
The `web-print-fonts-libertinus-7.051-v1` release carries eight unsubsetted
Libertinus Serif, Sans and Math WOFF2 faces and 1,685,928 payload bytes. Font
software retains its [SIL OFL-1.1 notice](LICENSES/OFL-1.1-Libertinus.txt);
project-created SVG contributions retain the source project's content terms
and its third-party exclusions.

These assets support explicit cold-cache bootstrap. They are render products
and font software, not historical source evidence or new editorial, rights or
visual approval. The controlling Triptych registry binds exact bytes to current
canonical sources; normal resolution is offline, while downloading is explicit.
Hot browser-print products embed verified asset bytes and require no asset-cache
hydration or native renderer for publication. Each release includes the pinned
registry, delivery sidecar, role-specific record, README, license notice and
checksums. The strict helper, rather than manual TAR extraction, validates
archive and member hashes, membership and types before cache use.

The canonical TeX/PNG source closure matches Triptych commit
`7b9daae87c00b0e4d84fe958372d520300374c08`. That commit predates the new registry
and implementation. Their uncommitted preparation bytes and original renderer
fingerprints are separately pinned in the release records; no generator or
registry commit is fabricated. Font inputs instead come from the exact pinned
upstream CTAN Libertinus 7.051 distribution.
